# Выгрузка результатов JSON 1.0

Формат соответствует приложению «Как сдать результаты» к студенческому гайду.
В публичной поставке нужны два файла:

- `results/dev/results.json`: все 65 исходных ID, 60 чатов и 5 звонков.
- `results/prod/results.json`: все 10 исходных ID контрольных чатов.

Не создавайте фиктивные записи контрольного набора до его получения.

```powershell
python tools/export_results.py --dataset dev --group-id DEV --team-name "Фактическое название команды"
python tools/export_results.py --dataset prod --group-id ВЫДАННЫЙ_GROUP_ID --team-name "Фактическое название команды"
python tools/export_results.py --dataset dev --validate-file results/dev/results.json
python tools/export_results.py --dataset prod --validate-file results/prod/results.json
```

Для сдачи текущего проверенного провайдера добавьте `--current-provider` при
заданных `CQA_MODEL` и `CQA_THINK`. Либо задайте точный фильтр:
`--model-filter qwen3:8b --prompt-revision operator-evidence-v7 --think 1`.
Старые оценки другой модели, ревизии или режима не подставляются вместо
отсутствующего текущего результата: соответствующий ID получает `status="error"`.
Без фильтра выбирается последняя настоящая официальная оценка независимо от
ревизии; это полезно для исторического экспорта, но не подтверждает её качество.

`--include-external` явно разрешает оценки внешней модели из подтверждённого
запуска Codex CLI (`verified_run=true`, `official-grounded-batch-v1`). Локальные
фильтры продолжают ограничивать Ollama; проверенный внешний результат может
использоваться отдельно. Выбирается последняя подходящая оценка на исходный ID.
Внешняя модель указывается собственным фактическим именем, а не именем Qwen:
`model.mode` становится `external_api` либо `hybrid`, если в файле есть оба
провайдера. Без явного флага внешние и тестовые записи не подставляются.
Контрольный PROD (FBroker) оценён Claude Code напрямую (`engine=claude-code`,
`claude-direct-grading-v1`, модель claude-opus-5-5) и принимается тем же флагом.

`--require-complete` дополнительно запрещает записи с ошибками. Без этого флага
ошибки допустимы по формату организаторов: ID сохраняется, `status="error"`,
`criteria=[]`, `score=null`, безопасная причина в `error`. Ошибка не заменяется
нулевой оценкой и не скрывается из набора.

По умолчанию экспортируется первоначальный результат настоящей локальной модели,
а не ручное исправление. Используется последняя сохранённая оценка по неизменённым
официальным определениям и правилам расчёта. Пользовательские критерии, тестовый
провайдер и старые записи без происхождения модели не выдаются за эту оценку.
`--reviewed` явно выбирает финальные результаты с решениями проверяющего.
Оба режима сохраняют исходную историю приложения. В `model.name` перечисляются
фактически записанные названия локальных моделей выбранных оценок.

Если успешных оценок ещё нет, укажите фактически использовавшуюся при попытках
модель через `--model-name`; наличие этого параметра не создаёт ни одной оценки.
Имя команды обязательно; шаблон «Название команды» не принимается.

Восемь кодов критериев: `contact`, `discovery`, `identification`, `consultation`,
`empathy`, `dialogue`, `closure`, `critical`. Числовые значения — исходная ступень
шкалы, а не взвешенный вклад. `evidence_turns` нумеруется с 1 по исходному массиву,
включая клиента, оператора, бота и систему. Проверенный участок раскрывается в
соответствующий диапазон номеров; объяснение N/A сохраняется в `rationale`.
Если для N/A модель не указала конкретных реплик, честно сохраняется
`evidence_turns: []`: N/A не является ошибкой обработки. Для применимых
критериев пустой список доказательств не допускается; отсутствующее действие
должно иметь проверенный участок.

Выгрузка не включает текст всего диалога, аудиоссылки, ключи, внутренние идентификаторы
оценок и служебные журналы. Из обоснований удаляются ссылки, адреса электронной
почты, телефоны, IBAN и распознаваемые ключи; значения и номера реплик сохраняются.
Обоснования предназначены для сдачи; перед публикацией
проверьте их на лишние персональные сведения. Проверка схемы и арифметики не
подтверждает смысловую правильность ответа модели.

Экспорт выполняется атомарно в UTF-8. Изменение файлов само по себе не отправляет
их в Git: проверьте оба файла, сделайте commit и push до стоп-кода.
