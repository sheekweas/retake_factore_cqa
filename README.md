# CQA - контроль качества диалогов

Команда: **retake factory**.

Веб-приложение для оценки работы оператора: редактируемые чек-листы, импорт разговоров, обоснования с переходом к исходной реплике, N/A, взвешенные результаты и апелляции с сохранением первоначальной оценки.

Интерфейс: HTML, CSS и JavaScript. Сервер и SQLite: Python, без обязательных сторонних зависимостей. Оценка выполняется локальной моделью через Ollama; регистрация для демонстрации не требуется.

## Быстрый запуск

```powershell
git clone https://github.com/sheekweas/retake_factore_cqa.git
cd retake_factore_cqa
```

Сервер использует только стандартную библиотеку Python, `pip install` для основного сценария не нужен. Работает на Windows, Linux и macOS; на Linux/macOS вместо `$env:NAME = 'value'` используйте `export NAME=value`.

Нужен Python 3.11+ и работающий Ollama с моделью qwen3:8b. Установите Ollama с официального сайта, затем загрузите модель:

```powershell
ollama pull qwen3:8b
```

Если Ollama ещё не запущен, запустите `ollama serve` в отдельном терминале. Для хранения моделей внутри проекта задайте `OLLAMA_MODELS` перед запуском Ollama. Уже работающий сервер использует собственное расположение моделей.

На видеокарте с 8 ГБ памяти перед запуском Ollama можно задать `OLLAMA_FLASH_ATTENTION=1`, `OLLAMA_KV_CACHE_TYPE=q8_0` и `OLLAMA_NUM_PARALLEL=1`: это позволяет сохранить контекст 16384 без переноса части модели на CPU. Фактическое размещение проверьте командой `ollama ps`; параметры зависят от доступной памяти. Портативный скрипт использует эти значения по умолчанию только при запуске собственного сервера. [Настройки памяти Ollama](https://docs.ollama.com/faq).

В каталоге проекта:

```powershell
$env:CQA_MODEL = 'qwen3:8b'
$env:CQA_THINK = '1'
$env:CQA_NUM_CTX = '16384'
$env:CQA_MODEL_TIMEOUT = '600'
python -m server.app
```

Открыть **http://127.0.0.1:8000/**. Другой порт: `python -m server.app --port 8001`. База сохраняется в `.local/cqa.sqlite3`. Сервер доступен только локально; он не предназначен для открытого хостинга без дополнительной защиты.

Для портативного Ollama на Windows распакуйте официальный пакет в `.local/ollama`, затем используйте:

```powershell
powershell -ExecutionPolicy Bypass -File scripts/start.ps1 -Model qwen3:8b -DownloadModel
```

Скрипт хранит модели в `.local/ollama-models`, журналы - в `.local/runtime`; `-RestartOwnedApp` перезапускает только подтверждённый собственный процесс. `/api/health` показывает настройку модели, а не проверку качества её ответов.

## Работа

1. **Импорт и оценка**: загрузите JSON, вставьте его либо получите набор через серверный API-адаптер. Выберите разговоры и версию чек-листа; пакетная оценка идёт последовательно.
2. **Диалоги**: фильтры языка/канала, транскрипт и история результатов. Ссылка в доказательстве выделяет исходную реплику; звонки имеют проигрыватель и переходы по времени.
3. **Чек-листы**: изменяйте формулировки, веса, типы, числовые ступени, секции и применимость N/A. Сохранение создаёт новую версию; старые оценки используют прежнюю конфигурацию.
4. **Апелляции**: подайте комментарий к критерию, затем отдельно подтвердите или измените ответ с причиной. Итог пересчитывается, первоначальная оценка и предыдущие решения сохраняются.

Для API организаторов задайте `CQA_DEV_URL` в окружении сервера либо сохраните выданный адрес в `.local/dev-url.txt`. В интерфейсе укажите нужный `group_id`. Адрес с подписью, реальные записи и транскрипты не входят в репозиторий. Пример структуры импорта - в `examples/`.

Исходные роли client/operator/bot/system и метки времени сохраняются. Оценивается работа оператора; остальные роли используются как контекст.

## Правила оценки

Начальная конфигурация содержит восемь официальных критериев. Веса 01–07: 10/15/20/20/15/15/5; 08 - отдельный флаг без баллов. Ступени 04: 0/5/10/15/20; 06: 0/4/7/10. N/A разрешён только по условиям 02/03/04/07. Применимые веса нормируются до 100, итог округляется до двух знаков (HALF_UP); секции показываются отдельно.

Модель и правила не зашиты в результат: каждая оценка сохраняет выбранную версию чек-листа и параметры провайдера. Изменённые критерии следуют собственным сохранённым формулировкам и шкалам, не наследуя противоречащие подсказки исходного чек-листа.

## Повторная расшифровка записей

Выданный транскрипт может содержать ошибки исходного распознавания. Дополнительный локальный модуль распознаёт настоящий аудиофайл и сохраняет отдельные сегменты с позициями относительно записи. Исходные ролевые реплики и доказательства прежних оценок не перезаписываются.

Необязательная установка (рекомендуется Python 3.13):

```powershell
py -3.13 -m venv .local/asr-venv
.local/asr-venv/Scripts/python.exe -m pip install -r requirements-asr.txt
.local/asr-venv/Scripts/python.exe tools/transcribe_calls.py --device cpu
```

Модель large-v3-turbo скачивается один раз, требует около 1,6 ГБ. Для ускорения на NVIDIA нужны совместимые CUDA 12/cuDNN 9 и режим `--device cuda`; скрипт обнаруживает DLL портативного Ollama и cuDNN в локальном окружении. На CPU используется int8. `--conversation ID` обрабатывает один звонок, `--force` повторяет распознавание. Без этих ключей готовые записи пропускаются. Аудио, модель, кеши и результаты остаются в `.local`.

В карточке доступны представление по записи и исходные реплики. Автоматические сегменты не определяют достоверно говорящего и не считаются проверенными человеком. Оценка оператора остаётся привязана к исходным ролям. Имена, числа и неразборчивые места требуют сверки со звуком; стопроцентная точность распознавания не гарантируется.

## Результаты для сдачи

Формат JSON 1.0 реализован по дополнению организаторов: DEV - 65 диалогов (60 чатов и 5 звонков), PROD - ровно 10 новых контрольных чатов. Нумерация evidence_turns начинается с 1 по исходному массиву, включая клиента, бота и системные события. Флаг грубой ошибки передаётся отдельно, N/A сохраняется как null. Ошибки обработки имеют status=error и score=null.

Пакетная оценка уже импортированного DEV, с продолжением после остановки:

```powershell
python tools/evaluate_dataset.py --group-id DEV --progress-file .local/dev-evaluation-progress.json
python tools/export_results.py --dataset dev --group-id DEV --team-name "retake factory" --model-filter qwen3:8b --prompt-revision operator-evidence-v7 --think 1
```

Выгрузка сохраняется в `results/dev/results.json`. `--require-complete` запрещает выгрузку с ошибками. По умолчанию экспортируется исходная автоматическая оценка; `--reviewed` явно выбирает пересмотренную человеком. Старые результаты другой модели или ревизии не подменяют текущие.

После получения контроля импортируйте фактический group_id и выполните:

```powershell
python tools/evaluate_dataset.py --group-id ACTUAL_GROUP --progress-file .local/prod-evaluation-progress.json
python tools/export_results.py --dataset prod --group-id ACTUAL_GROUP --team-name "retake factory" --model-filter qwen3:8b --prompt-revision operator-evidence-v7 --think 1
python tools/export_results.py --dataset prod --validate-file results/prod/results.json
```

Замените ACTUAL_GROUP выданным значением. До стоп-кода оба JSON нужно закоммитить и отправить push в публичный репозиторий. Файл PROD не создаётся из вымышленных ID, пока исходный набор не получен. Структура и примеры - в `docs/results-format.md`.

Для приоритета контроля DEV можно приостановить между запросами, создав `.local/STOP_EVALUATION`. Текущий запрос завершится. Удалите этот файл перед запуском PROD или продолжением DEV. Не запускайте конкурирующие пакеты на одной локальной модели.

## Автоматические проверки

```powershell
python -m unittest discover -s tests -q
node web/dev/ui_check.mjs
node web/dev/guide_acceptance_check.mjs
node web/dev/timeout_check.mjs
node web/dev/release_responsive_check.mjs
node web/dev/voice_view_check.mjs
node web/dev/results_export_check.mjs
node web/dev/default_checklist_check.mjs
```

Для браузерных проверок нужны Node.js 22+ и Chrome/Edge. Они используют отдельные базы и явно тестовый провайдер, не меняют рабочие данные и не измеряют точность реальной модели. Проверяются импорт, версии чек-листов, веса/N/A, исходные и пересмотренные результаты, безопасность вывода и адаптивность.

Реальный локальный провайдер проверяется отдельно: `python -m server.model_check --language RU`. Семантическая проверка: `python -m server.semantic_check --language EN --scenario completed`. Эти запросы используют синтетические разговоры, занимают время и не сохраняют оценки в рабочую базу.

## Модель и ограничения

По умолчанию qwen3:8b, thinking включён, контекст 16384. Одна локальная оценка - один запрос Ollama; оплаты внешнего API нет. На тестовом ПК наблюдались ответы примерно за 30–155 секунд; длинные диалоги могут занять больше, серверный тайм-аут - 600 секунд. Перед повтором после ошибки проверьте историю.

Объём генерации ограничен 8192 токенами (`CQA_NUM_PREDICT`, допустимо 512–32768), чтобы зациклившееся рассуждение не удерживало очередь до сетевого тайм-аута. Незавершённый ответ не становится оценкой: сохраняется явная ошибка пакета. После основной обработки его можно повторить ключом `--retry-errors`.

Структура, допустимые шкалы и ссылки проверяются сервером. Смысловое заключение может быть ошибочным: в частности, модель иногда неверно применяет правила завершения или приписывает оператору действие бота. Проверяйте доказательства; апелляция сохраняет первоначальный вывод. Пройденные тесты не означают безошибочную оценку любых разговоров.

Дикция и интонация не оцениваются. Исходные позиции реплик относительно записи могут иметь смещение; новые ASR-сегменты используют время аудиофайла. Готовый компонент Dynamics 365 не поставляется; интерфейс и API разделены для дальнейшей адаптации.
